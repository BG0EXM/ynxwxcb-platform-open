# 伊宁县委宣传部部务工作平台

> 版本：**V1.7.0**（更新日期：**2026-10-09**）

面向县级党委宣传部的内部部务工作平台，开源免费，可自部署。

- 🗂️ 收文管理（呈批单/传阅登记卡/热敏标签打印）、征求意见（跨单位回函协同）、材料下发（免密查收存证）、考勤点到（含迟到）、请假管理、公车报备、值守排班、工作日历、会务管理、公共资料、大事记、每周工作总结、加班管理、年休假管理、常委管理、通讯录
- ⚙️ Go + Vue3 + SQLite 单二进制部署，零运维
- 🔒 可配置的角色-功能权限矩阵（48个权限点），数据范围按科室/本人隔离
- 🛡️ 国家保密安全防线：全链路四维涉密智能审查（Word/PDF/扫描件OCR），严防非涉密网络违规涉密流转
- 🧱 应用级防火墙 (WAF)：多重URL解码防绕过、大请求内存防放大、安全阻断页与真实审计日志留痕
- 📜 操作日志审计（仅管理员），关键操作、WAF拦截、涉密违规留痕、中文可读
- 🛡️ 登录按用户名+IP 限流、失败锁定、令牌可即时吊销，密码至少 8 位
- 🔑 首次登录强制修改默认密码，保障账号安全
- 📄 各模块台账一键导出 Excel，支持 A4 打印与 80×50mm 热敏标签
- 📊 列表接口分页，数据量大时依然流畅
- ⚡ 前端按需加载，首屏体积控制在 ~356KB
- 🌐 完全离线可部署，Nginx / Caddy 均可，支持 IPv6

## 功能模块

| 模块 | 说明 |
|---|---|
| 收文管理 | 上级来文登记、呈批单/传阅登记卡/热敏标签生成打印、文件退回管理 |
| 征求意见 | 公文草案发起、全县单位范围管控、外链免密分发、各单位在线填报反馈与盖章件上传、防篡改锁定、台账导出与回函一键打包ZIP下载 |
| 材料下发 | 非回执类政务公文免密码下发、受邀单位实名经办人查收签收、阅读次数统计、查收进度追踪与台账导出 |
| 考勤点到 | 管理员晨会手工点到、月度/年度统计与打印 |
| 请假管理 | 年假及各类假期登记、假条一键打印（按请假天数自动匹配审批流程）、统计与 Excel 导出 |
| 公车管理 | 车辆基础信息（车架号/保险等）、用车报备、派车单打印 |
| 会务管理 | 会议录入、一键生成公文通知文本、匿名免密报名链接、参会登记（单位限额控制）、签到单导出 |
| 公共资料 | 共享资料发布与阅读 |
| 通讯录 | 按部门/姓名查询 |
| 值守排班 | 日历视图当天值守（至21:00收文）、可标记县委大院排班 |
| 工作日历 | 全屏大日历（按月/按年展示），各科室在格子中添加要做的工作，跨天连续显示，列表展示，Excel 导出（可单科室/全部） |
| 大事记 | 各科室每月重大事项，按年汇总整个宣传部并导出 Word（仅管理员） |
| 每周工作总结 | 各科室录入本周重点工作，管理员可增删改全部，导出 Word 汇总（仅管理员） |
| 加班管理 | 加班记录录入、加班统计与补休管理（8 小时=1 天），Excel 导出（仅管理员） |
| 年休假管理 | 管理员配置每人每年年休假天数，已休联动请假，普通用户只读（仅管理员可配置） |
| 常委管理 | 常委大事记，按年/月展示，录入/修改/删除，导出 Word（仅管理员） |
| 系统管理 | 用户、角色、部门管理（添加/改名/删除） |
| 权限管理 | 角色-功能权限矩阵，48 个权限点按角色勾选（仅管理员） |
| 操作日志 | 关键操作/登录/导出/WAF拦截/涉密阻断留痕，按模块/动作/日期/关键词查询（仅管理员） |

> 各模块台账（用车报备/请假/考勤/排班/收文/征求意见/材料下发）均支持 Excel 导出。

## 更新日志

### V1.7.0（2026-10-09）

**公文协同生态演进 · 跨单位征求意见与材料下发闭环，涉密审查引擎与应用级 WAF 防御基线重磅发布**

- 🌟 **核心业务：新增「征求意见」跨单位公文意见征求全流程闭环**
  - **任务发布与分发**：支持录入公文标题、发文字号、截止时间、征求单位范围（支持预置乡镇/科室快速多选与回车批量维护）、正文通知要点及 Word/PDF 双格式文稿上传。
  - **受邀单位免密通道（`/public/solicit/:id`）**：受邀单位通过唯一专属链接免密访问，支持在线查阅任务通知、预览/下载公文原件，填报本单位反馈意见（有/无意见）、经办人及联系电话，并上传盖章回函与修改稿。
  - **防篡改与截止硬锁定**：受邀单位成功提交后即刻锁定，再次访问仅支持凭据查阅与原件下载，严禁二次篡改；任务到期后系统全站自动硬锁定，严禁超时提交。
  - **管理端全景监控与协同**：
    - 单位反馈进度卡片化实时统计（已反馈/未反馈清晰区分）；
    - 针对特殊误填情况，支持管理员一键“重置该单位反馈”，解除锁定允许单位重新填报；
    - 支持一键导出全单位反馈汇总台账 Excel；
    - 支持一键将全量受邀单位上传的盖章回函与附件流式打包为 ZIP 压缩包下载，大幅提升归档效率。

- 🌟 **核心业务：新增「材料下发」无密码精准公文分发与查收签收**
  - **通知发布与原件共享**：支持发布下发通知、文号、通知正文、受邀查收单位范围及 PDF 公文原件。
  - **公开端免密查收（`/public/dispatch/:id`）**：受邀单位通过专属链接免密直达，查阅通知并下载文件，必须实名登记签收单位、经办人与联系电话方可完成查收。
  - **查收去重与阅读频次监控**：同单位首次查收锁定签收凭据与时间，后续重复打开自动递增阅读次数并保留首次签收记录，防止虚假刷数。
  - **管理端查收监控**：支持查看各单位查收明细与阅读次数，支持管理员重置单单位查收状态，支持一键导出材料查收台账 Excel。

- 🛡️ **核心安全：构建全链路「涉密智能审查引擎」防泄密防线（全新重磅）**
  - **多层级法定涉密特征库**：
    - **国家秘密**：深度识别「绝密」、「机密」、「秘密」、「秘密★期限」、「密级：秘密」等法定密级标引与符号特征，精准匹配定密规则，杜绝普通词语误伤；
    - **工作秘密**：严格监控「工作秘密」、「工作秘密★」等标识；
    - **内部敏感控制**：覆盖「内部资料」、「内部文件」、「内部掌握」、「不得外传」、「严禁外传」、「非公开发布」等非公开公文标识。
  - **全格式深层文档内容透视与解构**：
    - **Word (DOCX) 深度解构**：基于 OOXML 架构深度解包，不仅扫描正文（`document.xml`），更穿透覆盖所有页眉（`header*.xml`）、页脚（`footer*.xml`）、批注（`comments*.xml`）与元数据属性，识破隐藏在页眉角落的密级标识；
    - **PDF 原生流与字形编码映射提取**：结合纯文本流抽取与 PDF 底层 Stream 解压，支持自定义 CMap 编码映射还原、Hex 16进制转码及 GBK/UTF-16BE 字符集多重转译，有效防御字形混淆绕过；
    - **扫描件/图像化公文离线 OCR 审查**：无缝对接本地 Apple Vision OCR / Linux Tesseract OCR 引擎，对纯图片扫描件、拍照公文进行后台离线光学字符识别，彻底封堵“拍照/截图规避文本检测”的违规泄密途径。
  - **全链路上传防线阻断与前置拦截**：
    - 后端在公文收文、公文附件、征求意见文稿与各单位反馈回函上传时前置执行涉密体检，一旦检测到密级标识立即 403 阻断落盘并记录涉密安全预警日志；
    - 前端封装统一安全护盾（`secrecyGuard.js`），在界面层弹出醒目红色警示卡片，向操作人员明确提示涉密法律风险、违规规则与命中文本，强化政务保密意识。

- 🛡️ **核心安全：应用级防火墙 (WAF) 全域防御加固与双模响应升级**
  - **URL 多重编码防绕过**：重构 WAF 路由与参数匹配逻辑，在检测原始 URL 的基础上自动执行 `QueryUnescape` 与 `PathUnescape` 双重解码检测，彻底阻断利用 URL 多重编码构造非法注入指令的绕过风险。
  - **请求体智能检测与内存防放大**：
    - 对 POST/PUT 请求体增加 `1MB` 读取上限（`io.LimitReader`），杜绝恶意构造超大报文耗尽服务器内存（防 OOM）；
    - 智能识别并跳过 `multipart/form-data` 二进制大文件流的正则字符串匹配，将文件内容交由专用涉密引擎处理，消除大文件上传误报与内存堆积。
  - **真实安全审计日志接入**：
    - WAF 拦截事件完整持久化写入系统操作日志（`operation_logs`），实时记录攻击者来源 IP、关联用户、科室、受击路由及截获的危险参数片段，供管理员随时安全溯源。
  - **浏览器与 API 双模阻断响应**：
    - 浏览器直接访问或网页请求被拦截时，返回专门定制的**深色科技风中文安全阻断页面**（展示国徽/盾牌图标、403 警告、来源 IP 与受阻路由）；
    - Ajax / 接口请求被拦截时，规范返回标准 `application/json; charset=utf-8` 结构化报文（带 `WAF_BLOCK` 错误代码及客户端 IP），杜绝纯文本输出。

- ⚙️ **系统健壮性与架构基线修复（深度测试与缺陷排除）**
  - **系统冷启动高可用修复**：重构数据库 `seed()` 基础数据为幂等初始化机制，彻底解决全新空库首次初始化时管理员角色异常（role_id=0）与默认权限丢失的 P0 缺陷。
  - **公开端大附件上传放行**：入口全局 LimitBody 限流精准豁免公开征求意见反馈上传，打通 20MB 盖章附件提交通道。
  - **SQL 导出全量安全上限防护（军规 13）**：为日程备忘、加班台账、年休假配置、周总结、大事记、常委大事记等全站导出接口补齐 `LIMIT 10000` 强约束，杜绝无限制全表扫描进内存。
  - **统一标准 JSON 响应规范（军规 15）**：全面替换 JWT 鉴权中间件、角色校验中间件及导出分支的原生 `http.Error`，彻底杜绝 `text/plain` 导致的客户端解析异常与头信息覆盖。
  - **资产归档流转与自增序列维护**：
    - 完善用户删除业务逻辑，将删除用户历史名下的会务、征求意见、材料下发公共资产无缝划转至操作管理员，杜绝孤儿数据；
    - 将 V1.7.0 全部新增业务表统一纳入物理删除后的全局自增序列（sqlite_sequence）重置机制。
  - **前端异常捕获防御**：补齐 Layout 水印解析本地缓存时的异常日志追踪，防止静默吞没异常。

## 部署

系统由两部分组成，**都要放到服务器上**：
1. **主程序** `ynxwxcb-server`（编译出的可执行文件）
2. **static 文件夹**（前端网页文件）

> ⚠️ **【重要】服务端涉密 OCR 识别环境提示（可选）**：
> 本平台在服务端全面集成了文档涉密审查引擎。对于普通的 Word (`.docx`) 及电子文本 PDF，系统通过内置纯 Go 解码引擎完成内容解构，**服务器无需安装任何三方组件即可离线检测**。
> 若您的业务需要支持**扫描件公文、拍照图片、图片版 PDF** 的离线光学文字识别（OCR 审查），需在 Linux 生产服务器上安装通用 Tesseract OCR 引擎及中文字库（系统启动后将自动智能探测识别）：
> - **Ubuntu / Debian**：
>   ```bash
>   sudo apt-get update && sudo apt-get install -y tesseract-ocr tesseract-ocr-chi-sim tesseract-ocr-chi-tra
>   ```
> - **CentOS / RHEL / Rocky Linux**：
>   ```bash
>   sudo yum install -y epel-release && sudo yum install -y tesseract tesseract-langpack-chi_sim tesseract-langpack-chi_tra
>   ```
> - **说明**：未安装 Tesseract 时，系统自动无缝退化为“文件名 + Word XML 全文/页眉/页脚 + PDF 原始文本流/CMap”三重防御模式，常规文档上传与业务运行不受任何影响。

部署后服务器目录结构如下：

```
/opt/ynxwxcb/
├── ynxwxcb-server        # 可执行文件
├── static/             # 前端页面文件夹（与可执行文件同级）
├── config.json         # 配置文件
└── data/               # 运行时自动生成（数据库/上传文件）
```

**部署有两种方式，任选其一：**

---

### 方式一：本地编译好后上传（推荐，最简单，服务器不用装环境）

> 适合小白，你只需要在自己电脑上做两步，然后把两个东西传到服务器。

**第 1 步：在自己电脑上编译出可执行文件**

在电脑上打开终端（命令行），进入项目 backend 目录：

```bash
cd backend
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -o ynxwxcb-server ./cmd/server
```

> 前提：电脑上装了 Go 语言环境。没装的话，看文末「常见问题」里的安装方法。
> 如果你连 Go 都不想装，也可以找已编译好的 `ynxwxcb-server` 文件直接用。

**第 2 步：把两个东西传到服务器**

需要上传到服务器的就这两样（放进同一个目录，比如 `/opt/ynxwxcb/`）：

| 文件/文件夹 | 说明 |
|---|---|
| `ynxwxcb-server` | 编译出的可执行文件 |
| `static/` | 前端页面文件夹（用仓库 `backend/static/` 里的） |

**第 3 步：在服务器上运行**

```bash
cd /opt/ynxwxcb
./ynxwxcb-server -config config.json
```

> 用 systemd 托管可开机自启，见 `deploy/systemd/ynxwxcb.service`。

---

### 方式二：在服务器上直接编译（懂行的用，服务器要装 Go）

> 适合在服务器上有 Go 环境、且把源码传到服务器的人。

```bash
# 1. 把整个项目源码上传到服务器（含 backend、frontend 等）
# 2. 进入 backend 目录编译
cd backend
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -o ynxwxcb-server ./cmd/server

# 3. 把 static 文件夹放到与 ynxwxcb-server 同一目录，然后运行
./ynxwxcb-server -config config.json
```

---

> **关键点**：后端在**运行目录**下找 `static/` 文件夹，所以无论用哪种方式，`ynxwxcb-server` 和 `static/` 必须放在**同一目录**。仓库里的 `backend/static/` 已帮你准备好前端页面，直接把它作为服务器上的 `static/` 文件夹用即可。

**什么时候需要重新构建前端？**
只有当你想**修改前端界面**（换背景图、改文案、改界面布局）时，才需要用 `npm run build` 重新生成 `static/` 文件夹。不想改前端就完全不用管。

完整部署见 [docs/DEPLOY.md](docs/DEPLOY.md)（Nginx）或 [docs/DEPLOY-CADDY.md](docs/DEPLOY-CADDY.md)（Caddy）。

## 数据库升级

从旧版本升级到新版本，**只需替换主程序 `ynxwxcb-server` 后重启**，无需手动操作数据库。

- 程序启动时会自动检测数据库版本（`schema_versions` 表），按版本号顺序执行未执行的迁移
- 新增表 / 加字段 / 改结构都通过迁移自动完成，**已有数据完整保留**
- 升级前建议先备份：`bash backup.sh`（备份到 `/opt/ynxwxcb-backup/`）

> 迁移逻辑见 `backend/internal/database/database.go` 的 `migrations` 列表，每次版本升级只需追加一个迁移函数。

## 常见问题

**Q1：电脑没装 Go，怎么编译？**
- Windows：去 https://go.dev/dl 下载安装包，装完重启终端
- Linux：`sudo apt install golang`
- 如果实在不想装 Go，可以让已编译好的人给你一份 `ynxwxcb-server` 文件直接上传

**Q2：`CGO_ENABLED=0 GOOS=linux GOARCH=amd64` 是什么？**
- 表示"编译出 Linux 64 位系统能运行的程序"（不管你在 Windows 还是 Mac 上编译）
- 照抄这行命令即可，不用理解每个参数

**Q3：上传到哪里？**
- 可执行文件和 static 文件夹放**同一个目录**，建议 `/opt/ynxwxcb/`

**Q4：static 文件夹哪来的？**
- 直接用仓库里的 `backend/static/` 文件夹，整文件夹复制到服务器

**Q5：页面打开是 404 或空白？**
- 99% 是 static 文件夹没放对位置或没传上去
- 确认服务器上 `ynxwxcb-server` 和 `static/` 在**同一目录**
